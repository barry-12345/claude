## 1. 定位、交付形式、技术选型与运行规范

### 1.1 产品定位与交付形式
- **产品名称**：《糖果塔防对战》（Candy TD Battle）V1
- **核心定位**：面向情侣/双人好友的 PC 桌面浏览器轻量级高颜值实时 1v1 策略塔防对战游戏（附带单人 AI 陪练模式，单局 5–7 分钟，纯鼠标为主 + `Space` 快捷偷看）。
- **交付形式**：Node.js 静态资源托管 + WebSocket 权威对战服务器 + 原生 HTML5 Canvas 2D / Web Audio API 纯前端单页应用。无需前端构建打包器（零 Webpack/Vite 编译步骤），零外部图片/字体 CDN 强依赖，本地一键 `npm start` 启动后浏览器打开即玩。

### 1.2 技术选型与取舍理由

| 层级 | 选型方案 | 取舍理由 |
| --- | --- | --- |
| **后端权威逻辑** | Node.js（原生 `http` + 极薄 `ws` 库）<br>20 Hz（50ms/tick）固定步长仿真 | `ws` 安装极快且稳定，无重型框架负担；服务器权威仿真彻底杜绝作弊、双端状态分叉与假动作真相前端泄密；单核 2C/2GB 服务器可轻松支撑多桌并发。 |
| **前端渲染** | 原生 HTML5 Canvas 2D + ES Modules | 与 Node 共享 `constants.js` 配置常量，开发迭代零打包延迟；通过三层离屏缓存精确控制渲染性能，完全避开外部素材加载失败风险。 |
| **前端音效** | 原生 Web Audio API 程序化合成 | 零音频资产体积、无网络解码卡顿，清脆合成音天然契合马卡龙糖果 Q 弹调性。 |
| **会话与重连隔离** | `sessionStorage` 存放 `playerId` 与 `reconnectToken` | **刻意不用 `localStorage`**：同一台电脑开两个标签页测双人联机时彼此独立、互不顶号；同一标签页误触 F5 刷新后仍保留令牌，支持 20s 宽限断线重连。 |

### 1.3 端口规范与进程隔离（对齐 `preflight.md`）
1. **日常启动默认端口**：`PORT=3000`（服务端支持 `process.env.PORT || 3000` 环境变量覆盖）。
2. **流程验证端口隔离**：
   - **Builder**：`3100–3199`
   - **Reviewer**：`4100–4199`
   - **Tester**：`4500–4599`
3. **进程卫生**：各角色启动本地服务前须确认端口空闲并记录自身 PID/会话标识，结束前仅清理自身启动的进程与浏览器会话，严禁执行 `pkill` / `killall`。

### 1.4 子路径反向代理原生兼容规范
为确保未来可无缝部署至 `http://43.143.38.16:8080/<gameid>/` 类反向代理子路径：
1. `public/index.html` 中所有脚本、样式引用均使用相对路径（如 `./css/style.css`、`./js/main.js`、`./js/shared/constants.js`），严禁以 `/` 开头硬编码根路径。
2. 前端 WebSocket 连接 URL 动态推导自 `window.location`：
   - `const wsProto = location.protocol === 'https:' ? 'wss:' : 'ws:';`
   - `const basePath = location.pathname.replace(/\/[^/]*$/, '/');`
   - `const wsUrl = `${wsProto}//${location.host}${basePath}ws`;`
3. 服务端同时兼容路径以 `/ws` 结尾的 WebSocket 升级请求（兼容反代保留子路径转发与剥离前缀转发两种配置），静态文件按规范化相对路径解析并拦截目录穿越。

### 1.5 Mac Retina 2x 性能保障与 `?netdebug=1` 诊断规范
吸取过往项目在 Mac Retina 2x 高分屏下无上限画布 + 每帧重绘全矢量阴影导致掉帧的教训，V1 强制执行以下渲染性能红线：
1. **逻辑分辨率锁定 + DPR 封顶**：逻辑画布基准尺寸固定为 `1280 × 720`；物理分辨率缩放倍率严格封顶 `const dpr = Math.min(window.devicePixelRatio || 1, 2);`（最大物理像素 `2560 × 1440`），CSS 自适应容器保持 16:9 居中并做精确坐标反算。
2. **三层离屏缓存（Offscreen Canvas）**：
   - **静态地图缓存**：草坪纹理、香草奶黄折线路径、边框描边、不可建甜品装饰、可建格微网格线只在初始化或缩放变化时绘制一次到离屏 Canvas，每帧仅 `1` 次 `drawImage` 贴图。
   - **塔底座与静态部件精灵缓存**：每类糖果塔 1–3 级底座与柔和投影在启动时预烘焙至离屏精灵图，战斗每帧严禁调用高开销 `ctx.shadowBlur`（用双层半透明圆角底色替代），仅渲染旋转炮管、呼吸微缩放与状态贴纸。
   - **粒子与跳字固定上限对象池**：粒子池上限 `220` 个、金币/伤害飘字池上限 `60` 个；超限按环形队列覆盖最旧对象，消除战斗高峰期的 GC 抖动。
3. **50ms 快照线性插值**：客户端 60fps 渲染循环根据最新快照速度矢量/进度做平滑插值，网络波动下移动依然丝滑。
4. **`?netdebug=1` 实时性能浮层**：URL 携带 `?netdebug=1` 时，画布左上角出现半透明调试面板，实时显示：`FPS`、`Render(ms)`、`RTT(ms)`、`ServerTick(ms)`、`DPR`、`Entities(怪/弹/粒)`。

## 3. 关键机制细节

### 3.4 「3 秒糖果快递预警 + 假动作心理战」防泄密与时序规范
1. **严格防泄密网络约束**：
   - 当进攻方发起 `express_party`、`express_boss` 或 `express_feint` 时，服务端内部记录完整快递单 `{ id, sendType, isFake, createdTick, arriveTick }`。
   - **在 `tick < arriveTick`（前 3.0s = 60 ticks）期间，服务端下发给防守方客户端的 `incomingAlerts` 与 `game_event` 严禁包含 `isFake`、`sendType` 或任何可区分真假的属性！** 防守方只收到 `{ id, arriveTick, totalTicks: 60 }`。哪怕打开网络抓包或 `?netdebug=1` 也绝对无法提前窥破真假。
   - 进攻方自己的界面可以看到「已发出：🚚 狂欢箱 / 🎩 假动作（剩余 2.1s）」，增强操纵爽感。
2. **到达瞬间（`tick === arriveTick`）结算**：
   - 真快递：触发 `express_arrived_real`，入口粉车打开后门，喷出包装纸屑粒子并按 `0.35s` 间隔吐出全部真实快递怪。
   - 假动作：触发 `express_arrived_feint`，入口粉车打开后门，“噗”地喷出漫天五彩纸屑和巨大俏皮气泡 `「😜 空快递盒！骗到你啦~」`，持续 `2.2s` 淡出，**对防守方造成 0 伤害、不刷新任何可扣血单位**；同时攻方已于点击时稳稳收下 `+5 Eco`。
3. **排队上限**：同一时刻在途未到的快递预警最多允许 `2` 辆并行排队（第 3 次点击返回 `EXPRESS_QUEUE_FULL` 轻提示，冷却与金币均不扣除）。

### 3.5 「防误触偷看对手」平滑镜头与状态保护
- **状态变量**：`peekActive = isHoveringPeekZone || isSpaceHeld`；`peekProgress ∈ [0, 1]`。
- **平滑缓动**：进入偷看时 `peekProgress` 在 `260ms` 内按 Cubic Ease-Out 趋近 `1`；退出偷看时在 `200ms` 内按 Cubic Ease-Out 归零。
- **画面表现**：当 `peekProgress > 0` 时，己方地图容器按 `-peekProgress * 1280` 向左平推，对手实时地图按 `(1 - peekProgress) * 1280` 从右侧同步滑入；对手画面四周亮起柔粉紫脉冲虚线框，顶部居中展示半透明提示条「👀 正在偷看对手战场（移开鼠标或松开 Space 立即回防）」。
- **交互硬保护**：一旦 `peekActive === true || peekProgress > 0.05`：
  - 自动隐藏己方建塔虚影预览、禁用地图网格点击建塔/选塔/升级/出售操作。
  - 底部右侧「派怪与快递区」仍保持完全可用，方便偷看对手防线弱点后直接点怪压制。

### 3.6 联机房间状态机与 20 秒断线重连宽限
- **房间状态**：`LOBBY` → `COUNTDOWN (3s)` → `PLAYING` ⇄ `PAUSED_RECONNECT (20s)` → `ENDED`。
- **关键异常边界处理**：
  - 房主在 `LOBBY` 离开：若仍有 P2 在房内，自动转移房主权给 P2；若空房则销毁。
  - 双人 `PLAYING` 时一方 WS 断开：服务端立即将房间切入 `PAUSED_RECONNECT`，冻结双方所有仿真 ticks，记录 `reconnectDeadlineMs = now + 20000`，向在线方广播倒计时。
  - 重连恢复：客户端携带 `sessionStorage` 中的 `{ roomCode, playerId, reconnectToken }` 发送 `join_room`，服务端校验令牌匹配后恢复该连接为对应槽位，下发最新完整 `game_snapshot` 并在短暂缓冲提示后恢复 `PLAYING`。
  - 超时裁决：若 `20s` 倒计时归零掉线方仍未回归，自动判在线方为胜者并转入 `ENDED`；若双方同时掉线超过 `20s`，回收销毁房间释放内存。

### 3.7 单人 AI 陪练策略（两档难度）
AI 完全通过与真人玩家一致的 `applyPlayerAction(sim, aiPlayerIndex, action)` 渠道下指令，无任何隐形作弊加钱：
- **决策周期**：每 `20 ticks`（`1.0s`）评估 1 次。
- **布局优先序**：
  1. 开局优先在弯道黄金格（如 `(3,3)`、`(5,5)`、`(8,5)`、`(10,2)`）建造 `1 座草莓 + 1 座薄荷减速`。
  2. 检测到自身已有 2 座塔或对方开始发 `toffee` / 进入第 4 波，优先补充 `1 座柠檬破甲狙` 与 `1 座焦糖爆米花`。
  3. 金币溢出时优先将核心弯道塔升至 Lv2/Lv3，其余投入进攻派怪。
- **两档性格差异**：
  - **休闲甜心（`casual`）**：决策间隔 `1.8s`，偏稳健防守，较少抢 Eco（每 `16–22s` 派 1 次软糖），第 7 波后偶发真快递，**不使用假动作**。
  - **狡黠狐狸（`clever`）**：决策间隔 `1.0s`，积极卡冷却派软糖/泡泡糖拉高 Eco，若发现玩家无柠檬狙则针对性派 `toffee`，且会在资金充足时主动穿插 **`🎩 虚晃假动作`** 与 **`🚚 真快递`** 迷惑玩家。

## 5. 可控测试条件与测试钩子（与生产彻底隔离）

### 5.1 双重门控隔离机制
1. **服务端环境变量门控**：只有服务端启动时显式注入 `CANDY_ALLOW_TEST_HOOKS=1`（如 `npm run start:test`）才会受理 `test_command` 消息；普通生产启动（`npm start`）收到任何测试指令均直接拦截并返回 `{ code: 'TEST_HOOKS_DISABLED' }`。
2. **客户端 URL 门控**：只有当前页面 URL 携带 `?test=1` 时，`main.js` 才会挂载 `window.__CANDY_TEST__`；**普通入口 URL 绝不暴露任何测试钩子与测试界面**。
3. **测试钩子不替代正常入口端到端验证**：`AC-01`（单人 AI 全流程）与 `AC-02`（双人开房联机全流程）必须从**无 `?test=1` 的纯正常入口**跑通。

### 5.2 受控测试接口清单（仅 `?test=1` + `CANDY_ALLOW_TEST_HOOKS=1` 生效）
| 方法名（`window.__CANDY_TEST__.*` / WS `test_command`） | 参数与功能说明 | 主要支撑验收项 |
| --- | --- | --- |
| `getSnapshot()` | 返回权威状态完整 JSON（tick、phase、wave、双方血量/金币/Eco、塔列表、小怪位置与状态、在途快递与真实属性仅限测试端观测） | 全量断言校验 |

## 6. 工作包执行模式与前后端接口契约

### 6.1 构建模式：**单 Builder 顺序实现**
本 V1 采用**单 Builder 顺序实现**，按 `Layer 1 共享数值+纯仿真与单测` → `Layer 2 WS 房间+AI+协议集成测` → `Layer 3 前端渲染+防误触偷看+Web Audio+交互自测` 依次推进，确保共享常量、WS 协议及假动作隐秘字段裁剪零错位。

### 6.2 核心前后端 WebSocket 协议契约

#### (1) Client → Server 消息
| `type` | 必填字段 | 规则与错误码 |
| --- | --- | --- |
| `create_room` | `{ mode: 'pvp'\|'ai', aiDifficulty?, nickname, playerId?, reconnectToken? }` | 20 字内昵称过滤 XSS；`pvp` 返回 4 位 `roomCode`；`ai` 初始化双阵营 |
| `join_room` | `{ roomCode, nickname, playerId?, reconnectToken? }` | 匹配 `reconnectToken` 走重连恢复；否则满 2 人返回 `ROOM_FULL`，无房返回 `ROOM_NOT_FOUND` |
| `player_ready` | `{ ready: boolean }` | 双方均 `true` 后触发 3s `COUNTDOWN` |
| `place_tower` | `{ towerType, col, row }` | 校验是否在 `PLAYING`、网格合法空闲、金币充足；否则返回 `INVALID_CELL` / `INSUFFICIENT_GOLD` |
| `upgrade_tower` | `{ towerId }` | 校验归属、未满 Lv3、金币充足；否则返回 `MAX_LEVEL` / `INSUFFICIENT_GOLD` |
| `sell_tower` | `{ towerId }` | 校验归属后移除并返还 `Math.round(invested * 0.7)` |
| `set_targeting` | `{ towerId, targeting: 'first'\|'strong'\|'close' }` | 即时变更权威塔索敌规则 |
| `send_wave` | `{ sendType }` | 6 种类型之一；校验冷却、金币；真/假快递额外校验对手在途快递数 `< 2`（超限返回 `EXPRESS_QUEUE_FULL`） |
| `rematch_request` | `{}` | 仅 `ENDED` 态有效，双方同意（或 AI 局单方）后重置为全新 `tick=0` 对局 |
| `ping` | `{ clientTime }` | 原样回传 `clientTime` 并附带服务端 `serverTickMs` 供 `?netdebug=1` 计算 RTT |
| `test_command` | `{ action, payload }` | 仅 `CANDY_ALLOW_TEST_HOOKS=1` 时生效，否则返回 `TEST_HOOKS_DISABLED` |

#### (2) Server → Client 消息
- `room_state`：`{ roomCode, mode, phase, playerSlot, playerId, reconnectToken, players: [{ slot, nickname, ready, connected }], countdownSec, reconnectRemainSec }`
- `game_snapshot`（20Hz 同步核心包）：
  ```json
  {
    "type": "game_snapshot",
    "tick": 320,
    "phase": "PLAYING",
    "wave": 3,
    "nextWaveInTicks": 185,
    "ecoPayoutInTicks": 40,
    "self": {
      "hp": 20, "gold": 195, "eco": 35,
      "sendCooldowns": { "express_party": 0, "express_boss": 0, "express_feint": 240 },
      "towers": [{ "id": 1, "type": "mint", "col": 4, "row": 4, "level": 2, "invested": 205, "targeting": "first", "angle": 1.2 }],
      "creeps": [{ "id": 12, "type": "toffee", "hp": 110, "maxHp": 145, "progress": 0.42, "slowTicks": 35, "armored": true, "x": 410, "y": 296 }],
      "incomingAlerts": [
        { "id": 7, "arriveTick": 360, "totalTicks": 60 }
      ],
      "outgoingAlerts": [
        { "id": 8, "sendType": "express_feint", "arriveTick": 380, "totalTicks": 60 }
      ]
    },
    "opponent": {
      "hp": 18, "gold": 140, "eco": 40,
      "towers": [ "..." ],
      "creeps": [ "..." ],
      "incomingAlerts": [ "..." ]
    },
    "endedResult": null
  }
  ```
  > **契约硬红线**：`self.incomingAlerts`（对手发给我的快递）在 `tick < arriveTick` 前**绝对不携带** `sendType` 或 `isFake`！仅 `self.outgoingAlerts`（我自己发给对手的快递）带 `sendType` 以便我方状态条显示自己发出的真假标记。
- `game_event`：单发视觉/音效脉冲事件批（如 `eco_payout`, `express_started`, `express_arrived_real`, `express_arrived_feint`, `tower_shot`, `creep_pop`, `life_lost`）。
- `action_error`：`{ type: 'action_error', code, message }`。
