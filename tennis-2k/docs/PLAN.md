## 一、定位、交付形式与技术选型

### 1.1 产品定位
打造一款具备 **NBA 2K 级竞技质感与转播沉浸感**，同时保持 **轻部署、轻运行、30 秒上手但上限高** 的电脑浏览器 1v1 3D 网球游戏。

### 1.2 交付形式与目录架构
采用单仓库 npm workspaces（`tennis-2k/` 下设 `shared/`、`client/`、`server/`），前后端共享一套确定性 TypeScript 物理与规则引擎：

```text
tennis-2k/
├─ package.json                # npm workspaces 根配置与统一脚本
├─ tsconfig.base.json          # 共享严格 TypeScript 配置
├─ docs/                       # PLAN.md / SPEC.md / CONTRACT.md / review/
├─ shared/                     # 纯 TS 确定性物理、Magnus 旋转、规则状态机、AI、协议与镜像转换
├─ client/                     # Vite + TS + Three.js 3D 渲染、C2 角色、A1 操控、Web Audio、HUD
└─ server/                     # Node + TS + ws 60Hz 权威联机服务、4位房间码、15s 断线重连
```

### 1.3 核心技术选型与取舍理由

| 层级 | 选型 | 取舍理由与轻量硬约束 |

## 三、关键机制精确参数

### 3.1 3D 球场坐标系与标准尺寸（右手坐标系，单位：米 `m`）
- **原点 `(0, 0, 0)`**：球网正中央地面点。
- **`X` 轴（横向）**：单打边线 `±4.115 m`（总宽 `8.23 m`）；双打视觉边线 `±5.485 m`（仅美术显示）；球员可跑动横向边界 `X ∈ [-7.5, +7.5]`。
- **`Y` 轴（竖直向上）**：地面 `Y = 0`；球网高度 `netHeight(x) = 0.914 + (1.07 - 0.914) * min(1, |x| / 4.57)`；网球半径 `R_ball = 0.0335 m`。
- **`Z` 轴（纵向）**：底线 `±11.885 m`（全场 `23.77 m`）；发球线 `±6.40 m`；球员可跑动纵向边界：
  - **规范端 P0（房主 / 单机玩家，`side = +1`）**：`Z ∈ [+0.65, +16.0]`，面向 `-Z` 击球；
  - **规范端 P1（客场 / AI，`side = -1`）**：`Z ∈ [-16.0, -0.65]`，面向 `+Z` 击球。
- **标准近端视角相机（本地视图坐标）**：基础机位 `(0, 8.4, +19.2)`，视点 `(0, 0.7, -2.2)`，FOV `44°`，随本地玩家 `X` 轻微平滑跟随（`camX = clamp(playerViewX * 0.22, -1.6, 1.6)`）提升 2K 沉浸感但不晃晕。

### 3.2 1v1 联机近端视角镜像坐标转换公式
服务端与 `shared/` 引擎**始终运行在规范世界坐标系**下：
- **P0 客户端（`side = +1`）**：恒等映射，渲染与输入不做符号翻转。
- **P1 客户端（`side = -1`）**：绕 `Y` 轴旋转 `180°`（水平面中心对称）：
  - **渲染变换（World → LocalView）**：
    $$(x_v, y_v, z_v) = (-x_w,\; y_w,\; -z_w),\quad (v_{xv}, v_{yv}, v_{zv}) = (-v_{xw},\; v_{yw},\; -v_{zw}),\quad \text{yaw}_v = \text{yaw}_w + \pi$$
    于是 P1 自己永远位于 `z_v > 0`（屏幕下方近端），对手 P0 在 `z_v < 0`（屏幕上方远端）。
  - **输入变换（LocalIntent → WorldIntent）**：客户端发送屏幕直觉方向 `(aimX, aimZ)`（`W` 向上/深区 `-1`，`S` 向下/浅区 `+1`，`A` 向左 `-1`，`D` 向右 `+1`）。服务端按玩家 `side ∈ {+1, -1}` 统一映射：
    $$\text{worldMoveX} = \text{side} \cdot \text{aimX},\quad \text{worldMoveZ} = \text{side} \cdot \text{aimZ}$$
  - **对称性校验**：Deuce 区（偶数分）永远在当前发球方视角的右侧发往对手左侧；Ad 区（奇数分）永远在左侧发往对手右侧，双端体验完全一致。

### 3.3 3D 球体物理、Magnus 旋转与确定性球道解算
- **固定物理步长**：`dt = 1/60 s`，每 tick 内部执行 `2` 次子步进（`subDt = 1/120 s`），杜绝高速一发穿网或穿地。
- **加速度方程**：
  $$\vec{a} = (0, -9.81, 0) - k_d \|\vec{v}\| \vec{v} + k_m (\vec{\omega} \times \vec{v})$$
  其中空气阻力系数 `k_d = 0.022 m⁻¹`，Magnus 系数 `k_m = 0.00055`。
- **弹地物理（首次及二次触地 `y ≤ R_ball` 且 `v_y < 0`）**：
  - `v_y' = -e_y * v_y`；
  - `v_xz' = e_xz * v_xz + μ_spin * spinForwardBoost`（上旋加速前冲、下旋切削减速低弹）；
  - 旋转衰减 `ω' = 0.65 * ω`。
- **触网与擦网（`Z` 跨越 `0` 时线性插值交点 `(x_net, y_net)`）**：
  - `y_net < netHeight(x_net) - 0.02`：挂网（`v_z' = -0.15 v_z`，`v_x' = 0.25 v_x`，`v_y' = -0.1 |v_y|`）；
  - `netHeight(x_net) - 0.02 ≤ y_net ≤ netHeight(x_net) + R_ball`：擦网过网（水平速度 `× 0.65`；发球落入正确发球区判 `LET` 重发，不计失误；回合中比赛继续）。
- **ITF 压线界内判定**：球心首次触地点 `(x_b, z_b)` 计入球印半径 `R_mark = 0.0335 m`：
  - 单打区有效：`|x_b| ≤ 4.115 + R_mark` 且 `0 < |z_b| ≤ 11.885 + R_mark`（落于对方半场）；
  - 发球区有效：`0 < |z_b| ≤ 6.40 + R_mark` 且 `x_b` 位于目标对角发球框（带 `±R_mark` 宽容边）。
- **确定性球道解算器（Ballistic Solver）**：给定击球点 `P_hit`、目标落点 `P_target`（叠加品质散布）、球种预设旋转 `ω` 与飞行水平初速 `v_h`，通过 `3` 次牛顿/割线迭代修正空气阻力与 Magnus 偏移，解算出精确初速度向量 `V_0` 与过网安全余量。确保 `Perfect` 击球物理轨迹 100% 过网并精准命中目标区，绝不出现“绿爆莫名挂网”。

### 3.6 A1 极简纯键盘操控与 2K 绿条甜区公式
- **按键映射**（对战态阻止默认浏览器滚动）：
  - `W/A/S/D`（单机同步支持 `↑/←/↓/→`）：移动 + 击球松手瞬间的落点方向瞄准；
  - `J`（主攻 / 一发）：按住起脚下 2K 绿条，松手出球；回合中绿区打出高速平击/重上旋制胜球，发球时为高速高险一发；
  - `K`（变化球 / 二发）：默认低弹防守切削（Slice）；`W + K` 贴网放小球（Drop Shot，落点对方发球线前 `1.8–3.6 m`）；发球时为高上旋稳健二发；
  - `L`（挑高球 Lob）：高抛物线过顶（顶点 `5.2–6.8 m`）打向对方底线深区，克制上网。
- **绿条时间窗与品质分级**：
  - 蓄力进度 `p ∈ [0, 1.18]`，速率 `1.45 / s`（约 `0.69s` 满槽，超 `1.18` 强制挥拍判 `VERY_LATE`）。甜区中心 `p_sweet = 0.78`。
  - 动态窗口修正：`W_eff = W_green * M_shot * M_takeover * M_pressure`：
    - `M_shot`：一发 `J` = `0.82`，二发 `K` = `1.35`，常规 `J` = `1.00`，`K` 切削 = `1.18`，`W+K` 放小球 = `0.90`，`L` 挑高 = `1.10`；
    - `M_takeover`：Takeover 激活期 = `1.25`，否则 `1.00`；
    - `M_pressure`：自动滑步极限救球 = `0.78`，否则 `1.00`。
  - 误差 `e = |p - p_sweet|` 分级：
    - **`PERFECT`**（`e ≤ W_eff`，约 `75–105 ms`）：精准落点（压线瞄准可精准贴至边线内 `12 cm`）、球速 `× 1.16`、强旋转、绿色冲击波 + 甜点爆击音效、Takeover `+34`；
    - **`GOOD`**（`W_eff < e ≤ 2.4 * W_eff`）：随机散布 `±0.35 m`、标准球速 `× 1.00`、Takeover `+10`；
    - **`EARLY / LATE`**（`2.4 * W_eff < e ≤ 4.0 * W_eff`）：球速 `× 0.78`、球浅散布 `±0.95 m`，瞄边线有 `20%` 概率微出界；
    - **`VERY_EARLY / VERY_LATE`**（`e > 4.0 * W_eff`）：球速 `× 0.62` 且强偏移（早按易拉偏出边线，晚按易挂网/出底线）；一发红区必出界或挂网。
- **典型球速表（物理飞行速度 / 转播显示 km/h）**：
  - 一发 `J`：`36–46 m/s`（转播显示 `175–218 km/h`，保证人类 `0.48–0.65 s` 反应窗口）；
  - 二发 `K`：`26–32 m/s`（显示 `135–165 km/h`），上旋 `+65 rad/s`；
  - 底线 `J` Perfect：`27–33 m/s`（显示 `130–162 km/h`），上旋 `+45 ~ +70 rad/s`；
  - 切削 `K`：`16–20 m/s`，下旋 `-40 ~ -55 rad/s`。

### 3.7 火热槽（Takeover）与轻量 3D 鹰眼规则
- **Takeover**：容量 `0–100`；`Perfect +34`、`Good +10`、制胜分/Ace 额外 `+25`；非受迫性失误 `-25`、双误 `-30`。满 `100` 自动点燃，持续 **2 个完整得分回合**（`W_eff × 1.25`、起步加速 `+12%`、脚下金色火焰与尾迹），结束后清零并进入 `1` 分冷却期（不累计）。
- **轻量 3D 鹰眼特写**：
  - 触发条件：该球直接终结本分（Ace 压线、制胜压线球、出界球）或处于关键分（破发点/盘点/赛点/抢七），且首次触地点距最近有效边线/底线/发球线距离 `d_line ≤ 0.15 m`（`15 cm`）；
  - 演出流程：冻结常规物理 `1.8 s` → 相机平滑俯冲至落点旁 `0.8 m` 贴地特写 → 显示物理球印轨迹椭圆与发光边线 + `IN`（绿）/`OUT`（红）+ 精确毫米边距（如 `IN · 4.2 cm`）→ 自动恢复标准机位并清空键盘残留态进入下一分。

### 3.8 赛制状态机与 3 档单人 AI
- **Fast4（默认）**：局内 `0-15-30-40-Game`，`40-40` 直接打 **金球（Deciding Point）**；先赢 `4` 局且比分 `4-0 / 4-1 / 4-2` 胜出，`3-3` 进入 **7 分抢七**（先 7 且净胜 ≥ 2，胜者记 `4-3` 完赛）。自动标注 `BREAK POINT / DECIDING POINT / MATCH POINT / TIEBREAK`。
- **超级抢十（Super Tiebreak）**：单局先得 `10` 分且净胜 `≥ 2` 分获胜；首分后换发，之后每 `2` 分换发。
- **单人 AI（确定性可设种子 PRNG）**：
  - **新手（`rookie`）**：反应延迟 `240 ms`、跑速 `0.78×`、品质权重 `Perfect 10% / Good 55% / Early-Late 30% / Red 5%`、回球偏中路；
  - **进阶（`pro`）**：反应延迟 `140 ms`、跑速 `0.92×`、品质权重 `Perfect 32% / Good 50% / Early-Late 16% / Red 2%`、主动打反角与偶发 `W+K` 放小球；
  - **大师（`legend`）**：反应延迟 `70 ms`、跑速 `1.00×`、品质权重 `Perfect 58% / Good 35% / Early-Late 7% / Red 0%`、发球上网、大角度调动并对上网打 `L` 挑高球。

### 3.9 历史踩坑专项防护（DPR 防掉帧 + 断线重连防按键失灵）
1. **防 Retina 掉帧与高刷屏兼容**：
   - DPR 硬上限：`Math.min(window.devicePixelRatio || 1, 2.0)`；
   - 三档画质：`HIGH`（`dprCap=2.0`, 阴影 `1024`, 全粒子）→ `MEDIUM`（`dprCap=1.5`, 阴影 `512`, 半粒子）→ `LOW`（`dprCap=1.0`, 脚下 Blob 贴花阴影, 无冗余粒子）；
   - **降档**：滑动 60 帧窗口内超过 `30%` 帧耗时 `> 20 ms` 持续 `2 s` → 自动降一档；
   - **最多回升一次**：降档后若连续 `8 s` 平均帧耗时 `< 13.5 ms` 且 P95 `< 16.5 ms` → 回升一档，且全局 `upgradeCount ≤ 1`（彻底杜绝档位抖动）；
   - **高刷限帧**：启动采样 30 帧估算屏幕刷新率 `estHz`；**仅当 `estHz > 105` 时启用 `60 fps` 渲染节流**，`90Hz / 100Hz` 屏幕不限帧不误伤；
   - **`?netdebug=1` 悬浮窗**：实时显示 `FPS / MaxFrame(ms) / P95(ms) / QualityTier / ActiveDPR / DrawCalls / EstHz & Capped / RTT(ms) / Reconnects`。
2. **断线重连 15 秒与防按键失灵**：
   - 建房/入房签发 `sessionToken` 存于当前 Tab `sessionStorage`；
   - 断线后服务端立即暂停物理步进并广播 15 秒倒计时；15 秒内携 `roomCode + sessionToken` 重连收到 `FULL_SYNC` 后 3 秒倒计时恢复；超时判弃权；
   - **集中式 `InputController.resetAndRebind()`**：在 WS 重连成功、`FULL_SYNC`、鹰眼特写结束、`window` `blur/focus`、`visibilitychange` 及页面刷新重新挂载时，**强制清空 `pressedKeys`、重置蓄力槽、先解绑再重绑 `window` 键盘监听、移除弹窗焦点抢占**，彻底消除重连后按键失灵或卡键。

## 五、受控测试条件与测试钩子设计（与生产严格隔离）

为避免 Tester 耗时刷局或难以复现压线/断线/高刷屏场景，仅当 URL 包含 `?test=1`（后端仅在 `ENABLE_TEST_HOOKS=1` 时开放测试消息）挂载 `window.__COURT2K_TEST__`；**正常生产入口完全不挂载、零 UI 暴露**。

```ts
interface Court2KTestHook {
  /** 只读深拷贝状态快照（含比分、双人位置/流派/动作、球3D态、绿条、Takeover、鹰眼、画质/DPR/限帧、按键监听状态） */
  getState(): Readonly<TestStateSnapshot>;
  /** 固定 shared PRNG 种子，保证物理散布与 AI 决策 100% 可复现 */
  setSeed(seed: number): void;
  /** 一键跳至指定比分/局分/抢七/金球状态 */
  setScore(patch: ScorePatch): void;
  /** 设置指定玩家 Takeover 能量（0-100） */
  setTakeover(playerIndex: 0 | 1, value: number): void;
  /** 发射一记距有效线 distCm 厘米的确定性球，用于验证鹰眼 IN/OUT 触发边界 */
  triggerHawkeyeShot(opts: { inBounds: boolean; distCm: number; line?: 'sideline' | 'baseline' }): void;
  /** 向画质自适应管理器注入模拟帧耗时样本，验证降档与最多回升 1 次 */
  simulatePerfSpike(frameMs: number, durationMs: number): void;
  /** 覆盖估算刷新率（如 60/90/100/120/144），验证 >105Hz 限帧策略 */
  simulateRefreshRate(hz: number): void;
  /** 模拟客户端断网并在 reconnectAfterMs 后重连（传 -1 表示保持断线测超时判负） */
  simulateDisconnect(reconnectAfterMs: number): void;
}
```

> **测试红线**：钩子只用于加速验证局部状态与边界反例，**绝不替代正常入口端到端验证**（`AC-01`、`AC-10` 必须在不带 `?test=1` 的正常入口下跑通）。

### 6.2 跨包接口契约草案（定稿时独立固化为 `docs/CONTRACT.md`）
1. **`shared` 导出契约**：
   - 常量：`COURTS`（`hard | clay | grass`）、`ARCHETYPES`（`power | allcourt | serve_volley | defender`）、`COURT_DIM`；
   - 核心类/纯函数：`stepPhysics(state, inputs, dt)`、`solveBallisticShot(params)`、`createMatchState(config)`、`computeShotQuality(meterState, modifiers)`、`computeAIInput(state, difficulty, rng)`、`toLocalView(worldState, side)`、`toWorldInput(localInput, side)`。
2. **WebSocket 协议草案（相对路径 `<basePath>ws`）**：
   - **Client → Server**：
     - `CREATE_ROOM { court, format, archetype }`
     - `JOIN_ROOM { roomCode, archetype }`
     - `RECONNECT { roomCode, sessionToken }`
     - `READY {}` / `REMATCH_REQUEST {}`
     - `PLAYER_INPUT { seq, clientTime, aimX, aimZ, moveX, moveZ, action: 'none'|'J'|'K'|'L', phase: 'idle'|'hold'|'release' }`
     - `PING { t }`
   - **Server → Client**：
     - `ROOM_CREATED { roomCode, sessionToken, side: 1 }`
     - `ROOM_JOINED { roomCode, sessionToken, side: -1, matchConfig }`
     - `MATCH_START { serverTick, matchConfig, players }`
     - `STATE_SNAPSHOT`（30Hz 规范世界坐标：`tick, ball, players[0..1], score, takeover, phase, lastAckSeq`）
     - `GAME_EVENT`（`SHOT_HIT | BOUNCE | NET_LET | HAWKEYE_START | POINT_SCORED | TAKEOVER_ON | MATCH_OVER`）
     - `OPPONENT_DISCONNECTED { graceSeconds: 15 }` / `OPPONENT_RECONNECTED { resumeInSeconds: 3 }`
     - `FULL_SYNC { snapshot, matchConfig, yourSide }`
     - `PONG { t, serverTick }` / `ERROR { code, message }`（错误码：`ROOM_NOT_FOUND`、`ROOM_FULL`、`INVALID_TOKEN`、`MATCH_IN_PROGRESS`、`RATE_LIMITED`）

### 6.3 跨工作包端到端联调场景（在「整合评审第 1 轮」必验）

2. **`E2E-02`（联机鹰眼同步）**：联机中触发距边线 ≤15cm 压线球，验证双端同步切入 1.8s 3D 鹰眼特写并得出一致 `IN/OUT` 判定；
3. **`E2E-03`（断线重连与防按键失灵）**：联机对拉中客场断开 4 秒后重连，验证房主暂停倒计时、全量同步以及客场重连后立即按 `WASD/J/K/L` 正常操控（另测超 15 秒判弃权）；

## 七、待用户决策项与大任务预授权清单

### 7.1 待用户决策项（仅 2 项，可一键回复「都按推荐」）

1. **C2 风格化 3D 运动角色的建模实现路线**
   - **选项 A（推荐）**：纯 Three.js 程序化平滑关节风格化骨架（Smooth Capsule/Lathe 几何体 + 细化球拍 + 4 流派头饰/服饰/体型差异 + 毫秒级贴合 2K 绿条的挥拍/滑步动画机），同时抽象 `PlayerAvatarController` 接口预留后续替换 `.glb`。
     - *权衡*：开发稳定性极高（零骨骼权重穿模返工）、前端包体极轻、60fps 最稳；轮廓属于现代运动风格化（接近 Switch Sports 质感）而非手雕高精度网格。
   - **选项 B**：使用本机 Blender 5.2 Python 脚本预生成风格化角色 `.glb` 骨骼动画模型再由 Three.js 加载。
     - *权衡*：轮廓略更圆润，但自动化蒙皮与轴向对齐返工风险高、构建资产链路变重。

2. **1v1 联机赛后体验**
   - **选项 A（推荐）**：单机支持 `Esc` 暂停/重开；1v1 联机禁手动暂停，但赛后提供「一键再来一局（Rematch）」免重输房间码。
     - *权衡*：仅增 1 条协议消息，大幅提升好友连局体验。
   - **选项 B**：1v1 赛后直接回大厅，重新建房输入新房间码。
