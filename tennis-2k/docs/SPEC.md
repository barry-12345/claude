## 一、定位、交付形式与已批准技术选型

### 1.1 产品定位
打造具备 **NBA 2K 级竞技质感与转播沉浸感**，同时保持 **轻部署、轻运行、30 秒上手但上限高** 的电脑浏览器 1v1 3D 网球游戏。

### 1.2 交付形式与目录结构
采用单仓库 npm workspaces（`tennis-2k/`），前后端共享确定性 TypeScript 物理与规则引擎：

```text
tennis-2k/
├─ package.json                # npm workspaces 根配置（@court2k/shared, @court2k/client, @court2k/server）
├─ tsconfig.base.json          # 严格 TypeScript 基础配置
├─ docs/
│  ├─ PLAN.md                  # 初版规划归档
│  ├─ SPEC.md                  # 本文件（已批准定稿规格）
│  ├─ CONTRACT.md              # 跨工作包接口与 WS 协议契约
│  └─ review/                  # 各工作包与整合评审报告及证据目录
├─ shared/                     # @court2k/shared：纯 TS 确定性物理、Magnus 旋转、状态机、AI、镜像与协议
├─ client/                     # @court2k/client：Vite + TS + Three.js 3D 渲染、C2 角色、A1 手感、音效、HUD
└─ server/                     # @court2k/server：Node + TS + ws 60Hz 权威联机服务、4 位房间码、暂停与重连
```

### 1.3 已批准技术选型（含用户拍板决策）
1. **共享内核（`@court2k/shared`）**：纯 TypeScript、零运行时外部依赖、Vitest 单元测试。单机与联机 100% 复用同一套物理与规则代码，杜绝物理漂移。
2. **3D 前端（`@court2k/client`）**：`Vite + TypeScript + Three.js`。生产构建 gzip 总包体 **≤ 600 KB**，场景 Draw Calls **≤ 150**。
3. **C2 风格化 3D 运动角色（已拍板选项 A）**：
   - 采用 **纯 Three.js 程序化平滑关节风格化骨架**（Smooth Capsule / LatheGeometry 躯干与四肢、平滑球形关节、细化球拍框线与握把、4 流派球衣配色/头饰/体型差异、毫秒级贴合 2K 绿条松手瞬间的挥拍/引拍/随挥/滑步/发球抛球/庆祝动作混合机）。
   - 必须抽象统一的 `PlayerAvatarController` 接口（定义见 `CONTRACT.md` §4），预留未来无缝替换为 Blender 导出 `.glb` 模型的能力。
4. **联机服务端（`@court2k/server`）**：`Node + TypeScript + ws`，单进程 60Hz 权威步进、30Hz 状态快照广播，16 并发房间 RSS 内存 **≤ 256 MB**。
5. **程序化音效**：纯 Web Audio API 合成（零外部 mp3/wav），区分 3 场地击球/弹地音色、绿条爆击、擦网、鹰眼脉冲、观众掌声与关键分提示，支持一键静音与首次手势自动解锁。
6. **子路径反代兼容**：前端支持 `VITE_BASE_PATH`（默认 `/`），WS 连接自动按当前页面 `origin + basePath + 'ws'` 推导相对路径，严禁写死 `localhost` 或绝对 `/ws`。

## 三、关键机制精确参数与规则

### 3.1 3D 球场坐标系与标准尺寸（右手坐标系，单位：米 `m`）
- **原点 `(0, 0, 0)`**：球网正中央地面点。
- **`X` 轴（横向）**：单打边线 `±4.115 m`（总宽 `8.23 m`）；双打视觉边线 `±5.485 m`（仅美术）；可跑动横向范围 `X ∈ [-7.5, +7.5]`。
- **`Y` 轴（竖直向上）**：地面 `Y = 0`；球网高度 `netHeight(x) = 0.914 + (1.07 - 0.914) * min(1, |x| / 4.57)`；网球半径 `R_ball = 0.0335 m`。
- **`Z` 轴（纵向）**：底线 `±11.885 m`（全场 `23.77 m`）；发球线 `±6.40 m`；可跑动纵向范围：
  - **规范端 P0（房主 / 单机玩家，`side = +1`）**：`Z ∈ [+0.65, +16.0]`，面向 `-Z` 击球；
  - **规范端 P1（客场 / AI，`side = -1`）**：`Z ∈ [-16.0, -0.65]`，面向 `+Z` 击球。
- **标准近端视角相机（本地视图坐标）**：基础机位 `(0, 8.4, +19.2)`，目标点 `(0, 0.7, -2.2)`，FOV `44°`，横向柔和跟随 `camX = clamp(localPlayerViewX * 0.22, -1.6, 1.6)`。

### 3.2 1v1 联机近端视角镜像坐标转换公式
服务端与 `@court2k/shared` 始终在规范世界坐标系中演算：
- **P0（`side = +1`）**：恒等映射。
- **P1（`side = -1`）**：绕 `Y` 轴旋转 `180°`（水平中心对称）：
  - **渲染变换（World → LocalView）**：
    $$(x_v, y_v, z_v) = (-x_w,\; y_w,\; -z_w),\quad (v_{xv}, v_{yv}, v_{zv}) = (-v_{xw},\; v_{yw},\; -v_{zw}),\quad \text{yaw}_v = \text{yaw}_w + \pi$$
    使 P1 在自己屏幕上永远处于 `z_v > 0`（下方近端），对手 P0 在 `z_v < 0`（上方远端）。
  - **输入变换（LocalIntent → WorldIntent）**：客户端发送屏幕直觉方向 `(moveX, moveZ)` 与 `(aimX, aimZ)`（`W = -1` 向前/深区、`S = +1` 向后/浅区、`A = -1` 向左、`D = +1` 向右）。服务端按玩家 `side ∈ {+1, -1}` 转换：
    $$\text{worldX} = \text{side} \cdot \text{localX},\quad \text{worldZ} = \text{side} \cdot \text{localZ}$$
  - **对称性**：偶数分（Deuce 区）永远在当前发球方视角右侧发往对手左侧；奇数分（Ad 区）永远在左侧发往对手右侧。

### 3.3 3D 球体物理、Magnus 旋转与确定性球道解算
- **固定步长**：`dt = 1/60 s`，每 tick 内执行 `2` 次子步进（`subDt = 1/120 s`），防止高速球穿网或穿地。
- **动力学方程**：
  $$\vec{a} = (0, -9.81, 0) - k_d \|\vec{v}\| \vec{v} + k_m (\vec{\omega} \times \vec{v}),\quad k_d = 0.022\;\text{m}^{-1},\; k_m = 0.00055$$
- **弹地响应（`y ≤ R_ball` 且 `v_y < 0`）**：
  - `v_y' = -e_y * v_y`；
  - `v_xz' = e_xz * v_xz + μ_spin * spinForwardBoost`（上旋增强前冲，下旋降低前冲与弹跳）；
  - `ω' = 0.65 * ω`。
- **触网与擦网（球穿过 `Z = 0` 平面线性插值求 `(x_net, y_net)`）**：
  - `y_net < netHeight(x_net) - 0.02`：挂网（`v_z' = -0.15 v_z`, `v_x' = 0.25 v_x`, `v_y' = -0.1 |v_y|`）；
  - `netHeight(x_net) - 0.02 ≤ y_net ≤ netHeight(x_net) + R_ball`：擦网过网（水平速度 `× 0.65`；发球落入正确发球框判 `LET` 重发且不计失误；回合中继续比赛）。
- **ITF 压线界内判定**：首次触地坐标 `(x_b, z_b)` 计入接触半径 `R_mark = 0.0335 m`（球印边缘压线即界内）：
  - 单打区有效：`|x_b| ≤ 4.115 + R_mark` 且 `0 < |z_b| ≤ 11.885 + R_mark`（且落于对方半场）；
  - 发球区有效：`0 < |z_b| ≤ 6.40 + R_mark` 且位于目标对角发球框（含 `±R_mark` 边界）。
- **确定性球道解算器（`solveBallisticShot`）**：输入击球点 `P_hit`、目标落点 `P_target`（已叠加绿条品质散布）、期望水平初速/飞行时间、球种旋转 `ω` 与过网安全余量 `h_clear`，经 `3` 次迭代补偿阻力与 Magnus 偏移，解算出确定性初速度 `V_0`，确保 `Perfect` 球 100% 过网并落向目标点。

- **属性换算公式**：
  - 最大跑速：`v_max = 5.4 + (SPD - 60) * 0.048 m/s`（`5.98–7.03 m/s`），无冲刺键，按住方向 `0.28 s` 平滑提速至 `v_max`；
  - 极限救球自动滑步：预计到球时间 `< 0.55 s` 且人球水平距 ∈ `[1.3 m, 2.4 m]` 且持续朝落点移动时触发，触球有效半径由基础 `1.35 m` 延伸至 `1.80 m`；
  - 击球初速倍率：`1.0 + (POW - 80) * 0.008`；旋转倍率：`1.0 + (SPN - 80) * 0.010`；
  - 网前/放小球精度倍率：`1.0 + (NET - 75) * 0.012`；
  - 绿条甜区基础半宽：`W_green = 0.055 + (TIM - 75) * 0.0012`。

### 3.6 A1 极简纯键盘操控与 2K 绿条甜区
- **按键映射**（对战态调用 `e.preventDefault()` 防页面滚动）：
  - `W/A/S/D`（单机同步支持 `↑/←/↓/→`）：移动 + 松手出球瞬间的落点方向瞄准；
  - `J`：主攻（平击/重上旋制胜球）；发球时为高速高险一发；
  - `K`：变化球（默认低弹防守切削）；`W + K` 贴网放小球（Drop Shot，目标对方半场 `Z ∈ [1.8, 3.6] m`）；发球时为高上旋稳健二发；
  - `L`：挑高球 Lob（轨迹顶点 `5.2–6.8 m`，压向对方底线深区；发球准备阶段静默忽略）；
  - `Esc`：单机与联机均支持手动暂停 / 恢复（联机受 §3.8 防滥用规则约束）。
- **2K 绿条公式**：
  - 进度 `p ∈ [0, 1.18]`，增长速率 `1.45 / s`（超 `1.18` 自动强制挥拍判 `VERY_LATE`）；甜区中心 `p_sweet = 0.78`。
  - 有效半宽：`W_eff = W_green * M_shot * M_takeover * M_pressure`：
    - `M_shot`：一发 `0.82`、二发 `1.35`、常规 `J` `1.00`、`K` 切削 `1.18`、`W+K` 放小球 `0.90`、`L` 挑高 `1.10`；
    - `M_takeover`：Takeover 激活期 `1.25`，否则 `1.00`；
    - `M_pressure`：自动滑步救球 `0.78`，否则 `1.00`。
  - 误差 `e = |p - p_sweet|` 分档（**边界优先规则**：当 `p >= 1.18` 时无条件优先判 `VERY_LATE`，再执行下方区间判定）：
    - `PERFECT`（`e ≤ W_eff`）：精准命中（边线瞄准可精准压线 `12 cm`）、球速 `× 1.16`、强旋转、绿色冲击波+爆击音效、Takeover `+34`；
    - `GOOD`（`W_eff < e ≤ 2.4 * W_eff`）：散布 `±0.35 m`、标准球速 `× 1.00`、Takeover `+10`；
    - `EARLY / LATE`（`2.4 * W_eff < e ≤ 4.0 * W_eff`）：球速 `× 0.78`、变浅散布 `±0.95 m`，贴边瞄准有 `20%` 概率微出界；
    - `VERY_EARLY / VERY_LATE`（`e > 4.0 * W_eff`）：球速 `× 0.62` 且大幅偏移（早拉出边线/晚挂网或出底线），一发红区 100% 失误。
- **典型球速（物理飞行速度 / 转播显示 km/h）**：一发 `J` `36–46 m/s`（显示 `175–218 km/h`）；二发 `K` `26–32 m/s`（显示 `135–165 km/h`，上旋 `+65 rad/s`）；底线 `J` Perfect `27–33 m/s`（显示 `130–162 km/h`，上旋 `+45 ~ +70 rad/s`）；切削 `K` `16–20 m/s`（下旋 `-40 ~ -55 rad/s`）。

### 3.7 火热槽（Takeover）与轻量 3D 鹰眼
- **Takeover**：容量 `0–100`；`Perfect +34`、`Good +10`、制胜分/Ace 额外 `+25`；非受迫性失误 `-25`、双误 `-30`。满 `100` 自动激活，持续 **2 个完整得分回合**（`W_eff × 1.25`、起步加速 `+12%`、脚下金色火焰与拖尾），结束后清零并进入 `1` 分冷却期（不累计）。
- **轻量 3D 鹰眼特写**：
  - 触发：该球直接终结本分（压线 Ace/制胜分/出界）或处于关键分（破发点/盘点/赛点/抢七），且首次触地距最近有效线 `d_line ≤ 0.15 m`（`15 cm`）；
  - 流程：常规物理冻结 `1.8 s` → 相机平滑贴地特写至落点旁 `0.8 m` → 展示球印椭圆、发光线、`IN / OUT` 横幅与精确厘米距（如 `IN · 4.2 cm`）→ 平滑复位相机并调用 `InputController.resetAndRebind()`。

### 3.8 赛制状态机、单人 AI 与 1v1 联机手动暂停 / 重连 / Rematch 规则
- **Fast4（默认）**：局内 `0-15-30-40-Game`，`40-40` 金球（`DECIDING_POINT`）一球定胜负；先赢 `4` 局且 `4-0 / 4-1 / 4-2` 完赛，`3-3` 进入 **7 分抢七**（先 7 赢 2，胜者记 `4-3` 完赛）。自动标注 `BREAK_POINT / DECIDING_POINT / MATCH_POINT / TIEBREAK`。
- **超级抢十**：单局先得 `10` 分且净胜 `≥ 2` 分完赛；首分后换发，之后每 `2` 分换发。
- **单人 AI（可设种子确定性状态机）**：
  - `rookie`（新手）：反应延迟 `240 ms`、跑速 `0.78×`、品质 `10% / 55% / 30% / 5%`、保守中路；
  - `pro`（进阶）：反应延迟 `140 ms`、跑速 `0.92×`、品质 `32% / 50% / 16% / 2%`、反角与偶发放小球；
  - `legend`（大师）：反应延迟 `70 ms`、跑速 `1.00×`、品质 `58% / 35% / 7% / 0%`、发球上网+大角度调动+过顶挑高。
- **1v1 联机手动暂停与防滥用规则（用户已明确确认）**：
  - **触发与恢复**：对战进行中（`serve_ready / serve_toss / rally` 阶段），**双方均可按 `Esc`（或点击暂停按钮）触发手动暂停**；暂停期间**双方均可按 `Esc` 或点击「恢复比赛」发起恢复**（单机模式 `Esc` 暂停豁免次数与 60s 倒计时限制，并支持即时恢复）；
  - **防滥用限制**：每人每场最多主动暂停 **`3` 次**（`manualPausesLeft` 初始 `[3, 3]`，每触发一次扣减发起方 1 次；额度为 `0` 时服务端返回 `PAUSE_LIMIT_REACHED` 并提示“本场暂停次数已用尽”）；单次手动暂停上限 **`60 s`**，HUD 实时显示剩余倒计时与发起方，倒计时归零自动触发恢复；
  - **恢复前 3 秒倒计时与按键自愈**：无论手动点击恢复还是 60s 到时自动恢复，均先进入统一 **`3 s` 恢复倒计时（`resuming` 阶段）**，倒计时归零进入继续比赛瞬间，**双方客户端强制执行 `InputController.resetAndRebind()`**，彻底防止暂停恢复后按键失灵或卡键。
- **1v1 15 秒断线重连恢复**：
  - 建房/入房生成 `sessionToken` 存当前 Tab `sessionStorage`；
  - 任一方断线，服务端立即进入 `paused_disconnect` 暂停物理步进并广播 15 秒倒计时（此状态不消耗手动暂停次数，且不允许手动提前恢复）；
  - 15 秒内重连验证通过后下发 `FULL_SYNC`，走 `3 s` 恢复倒计时并执行 `InputController.resetAndRebind()`；超时 15 秒判断线方弃权（在线方胜）。
- **1v1 赛后一键 Rematch**：
  - 完赛态双方均可点击「再来一局」（发 `REMATCH_REQUEST`）；一方点击后通知双方等待确认，双方均确认后在同一房间号下立即开启新局，重置比分、统计、Takeover 及双方手动暂停次数为 `[3, 3]`。

### 3.9 历史踩坑专项防护（Retina 防掉帧 + 按键失灵自愈）
1. **DPR 与帧率自适应**：
   - DPR 硬上限 `Math.min(window.devicePixelRatio || 1, 2.0)`；
   - 画质三档：`HIGH`（`dprCap=2.0`, 阴影 `1024`, 全粒子）→ `MEDIUM`（`dprCap=1.5`, 阴影 `512`, 半粒子）→ `LOW`（`dprCap=1.0`, Blob 阴影, 关冗余粒子）；
   - **自动降档**：滑动 60 帧统计中，若连续 `2 s` 超过 `30%` 帧 `frameMs > 20 ms`，自动降一档；
   - **最多回升一次**：降档后若连续 `8 s` 平均 `frameMs < 13.5 ms` 且 P95 `< 16.5 ms`，允许回升一档，且全局 `upgradeCount ≤ 1`；
   - **高刷限帧**：启动采样 30 帧估算 `estHz`；**仅 `estHz > 105` 时启用 `60 fps` 渲染节流**，`90Hz / 100Hz` 不限帧；
   - **`?netdebug=1` 面板**：实时显示 `FPS / MaxFrame(ms) / P95(ms) / QualityTier / ActiveDPR / DrawCalls / EstHz & Cap / RTT(ms) / Reconnects`。
2. **集中式 `InputController.resetAndRebind()`**：
   - 统一挂载在 `window` 的 `keydown / keyup / blur / focus / visibilitychange`；
   - 在 **WS 重连成功、`FULL_SYNC`、手动暂停恢复、鹰眼特写结束、窗口失焦回焦、页面刷新重挂** 时，强制清空 `pressedKeys` 与蓄力态、解绑再重绑监听、移除按钮焦点（`document.activeElement?.blur()`）。

## 五、受控测试钩子设计（`?test=1` 严格隔离）

仅在客户端 URL 携带 `?test=1` 时挂载 `window.__COURT2K_TEST__`；服务端仅在环境变量 `ENABLE_TEST_HOOKS=1` 时受理 `TEST_COMMAND`（否则返回 `FORBIDDEN_TEST_HOOK`）。正常入口零暴露、零影响。

```ts
export interface Court2KTestHook {
  getState(): Readonly<TestStateSnapshot>; // 含比分、位置、流派、球3D态、绿条、Takeover、鹰眼、pause状态、画质/DPR/限帧、InputController绑定状态
  setSeed(seed: number): void;
  setScore(patch: ScorePatch): void;
  setTakeover(playerIndex: 0 | 1, value: number): void;
  triggerHawkeyeShot(opts: { inBounds: boolean; distCm: number; line?: 'sideline' | 'baseline' }): void;
  fastForwardPause(seconds: number): void; // 仅测试态：快进当前手动暂停/断线计时器，加速验证 60s 自动恢复与 15s 弃权
  simulatePerfSpike(frameMs: number, durationMs: number): void;
  simulateRefreshRate(hz: number): void;
  simulateDisconnect(reconnectAfterMs: number): void; // 传 -1 表示保持断线测试 15s 超时
}
```

> 钩子不得替代正常入口端到端验收（`AC-01`、`AC-10` 必须在不带 `?test=1` 的正常入口下跑通）。
