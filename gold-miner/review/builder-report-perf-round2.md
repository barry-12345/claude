## 问题 1(必须):90/100 Hz 屏幕上绘制次数减半,并被误降到最低画质

**原因:**
- 绘制上限原来写的是"距上次绘制不到 12 ms 就跳过"。90 Hz(11.1 ms)和 100 Hz(10 ms)的帧间隔都小于 12 ms,于是每两帧跳过一帧,绘制只剩每秒 45 / 50 次。
- 自动降档又把跳帧后 20–22 ms 的间隔当成慢帧,2 秒内就降到第 2 档。

**修改(index.html):**
- 跳过条件改为"距上次绘制不到 9.5 ms",也就是只在刷新率高于约 105 Hz 的屏幕上隔帧绘制。
  - 60/75/90/100 Hz 每帧都画,帧间隔就是屏幕本身的间隔,不会被误判为慢帧。
  - 120 Hz 每秒画 60 次,144 Hz 每秒画约 72 次。
- 自动降档的判断条件没有改(2 秒窗口内中位数 > 20 ms 或 90 分位 > 34 ms)。主动跳过的帧现在只出现在 ≥105 Hz 屏幕上,跳过后的间隔约 14–17 ms,不会触发降档。

**实测**(新测试 `tests/perfhz.js`,方法同评估员的 p6-hz.js:模拟各刷新率的 rAF;480×270 小画布;每个场景先测 8 秒,再继续观察到 15 秒)

| 刷新率 | DPR 2:每秒绘制 / 游戏时间 / 15 秒内最高画质档 | DPR 1.25:每秒绘制 / 最高画质档 |
|---|---|---|
| 60 Hz | 60.0 / 8 秒走 8.00 秒 / 0 | 60.1 / 0 |
| 60 Hz,间隔抖动 15–18 ms | 60.0 / 0 | 60.0 / 0 |
| 75 Hz | 75.0 / 0 | 75.0 / 0 |
| 90 Hz | 89.9 / 0 | 90.0 / 0 |
| 100 Hz | 99.9 / 0 | 100.0 / 0 |
| 120 Hz | 60.0 / 0 | 60.0 / 0 |
| 144 Hz | 71.9 / 0 | 72.0 / 0 |

- 所有场景的游戏时间都和实际经过的时间一致(差 ≤0.02 秒),游戏速度不受影响。
- 评估员的 p6-hz.js 用新版本复测:60/60 抖动/75/90/100/120/144 Hz 分别是每秒 60.0/60.0/75.0/90.0/100.0/60.0/71.9 次,画质档全部是 0。
- 慢机器仍会自动降档(`tests/perf-probe.js`,DPR2,1728×1117,CPU 4×,测 16 秒):画布降到 1728×972,16.5 FPS,p95 100 ms,D 132 ms。
- 不降速时停在原分辨率 3456×1944:48.6 FPS,帧时间中位数 16.7 ms,没有触发降档条件。

## 建议 1(已做):画质可以升回一档

- 连续 3 个检测窗口(共 6 秒)帧时间 90 分位都 < 18 ms 时,升回一档。
- 防止来回震荡:升档之后如果又因为慢被降下来,本页面就不再升档。
- 实测:
  - 在 4× 降速下一直停在最低档,没有升档,因为帧太慢。
  - 不降速时,一开始降到 1.5 倍后又升回原分辨率,之后没有再降。
  - 刷新率场景里,画质档始终是 0。
