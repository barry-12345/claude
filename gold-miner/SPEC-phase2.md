## 2. 技术路线与回归策略

1. **第 0 步(Builder 必做,先于任何修改)**:把当前 `index.html` 原样复制为 `tests/baseline-phase1.html`。保留 `tests/baseline.html`,它是第一阶段之前的版本,第一阶段的 AC-03 仍要用。
2. 仍是单文件 `index.html`,在现有代码上扩展,不重写。
3. **规则集**:新增 `const RULESETS = { 1: {...}, 2: {...} }`,当前规则对象为 `R`,版本为 `RULE_VERSION`(1 或 2)。本阶段改动的**每一个**数值或开关都从 `R` 读取,包括:
   - 目标数组(三个模式)、`STAR_MULT`;
   - 商店涨价率、第 1 关规则;
   - 开关:`finale`、`feel`(手感包里影响逻辑的部分,即顿帧)、`polish`(§7 的 a、d 两项)。
4. **版本选择**:
   - 默认 `RULE_VERSION = 2`;
   - URL 带 `?rules=1` 时用 1;
   - `__game.setRules(1|2)` 只在 start 屏有效,其它屏幕调用直接忽略。
   - `R` 在 `startGame` 时固定,一局之内不变。
5. **规则 1 = 第一阶段原样**。旧目标、旧星级、旧商店价格、旧单人商店(按一次 ↑ 就开始)、旧第 1 关生成;不刷尾声、没有顿帧。所有新逻辑都必须**在调用 `Math.random()` 之前**按 `R` 短路,保证规则 1 的随机序列和 `tests/baseline-phase1.html` 完全相同。
   - 只影响绘制、不碰逻辑状态和 `Math.random()` 的改动,两种规则下都可以生效:§7 的 b、c 两项,终局页"最终得分",V 键开关。
6. **视觉随机分流**:本阶段新增的纯视觉随机(粒子、镜头推近、金币雨、尘土、心跳暗角抖动)一律用独立的 `fxRand = mulberry(seed ^ 0x5f3759df)`(不带种子时用 `Date.now()`),**不得**调用 `Math.random()`。第一阶段已有的逻辑内粒子(`puff`、`boomFx` 等)保持原样。这样按 V 不会改变任何游戏结果(AC-P2-07)。
7. 新逻辑只依赖 `update(dt)`,保证 `advance()` 和实时运行一致。

## 3. #4 黄金尾声(三个模式,规则 2)

### 3.1 规则

| 项 | 规则 |
|---|---|
| 触发 | 本关 `G.time` 第一次 ≤ `15 × ROUND_TIME/60` 秒(快速模式为 2.5 秒),且尚未超时(`!G.timeUp`)。每关一次,`G.finaleOn = true` |
| 横幅 | `banner('黄金尾声!', '深处涌出宝藏 · 金块 ×1.5', '#ffd23a')`,屏幕轻震 0.3 |
| 刷新数量 | `FINALE_N = [3, 3, 4, 4, 4, 5, 5, 5]`(按关数) |
| 刷新种类 | 每个按权重抽:中金块 40、大金块 25、红宝石 10、翡翠 10、钻石 10、巨型金块 5(用 `weightedPick`,规则 2 下允许消耗 `Math.random`) |
| 位置 | 用现有 `freeSpot(ITEMS[type].r, [])`。它会避开现有物品和危险物,并保证存活玩家能够到。每个物品最多尝试 30 次,找 `y ≥ 430` 的位置;找不到就跳过这个物品 |
| 价值加成 | 尾声期间(到本关结束,包括超时的收尾阶段),`GOLD_TYPES`(含冰封金块)的 `pieceValue` 再 ×1.5。在淘金热和鉴定书之后相乘,每步 `Math.round` |
| 表现 | 新物品从地下"冒出"(0.4 秒缩放 + 金色光柱,视觉随机用 `fxRand`)。HUD 倒计时变金色并显示"尾声 ×1.5" |
| 每关重置 | `startRound` 里设 `G.finaleOn = false` |

### 3.2 与现有系统的交互

| 系统 | 规则 |
|---|---|
| 对战 | 两人抢同一批。刷新位置只要求**存活**玩家能够到;已淘汰的一方不参与 |
| 拔河 | 尾声物品可以被拔河,胜者按 ×1.5 后的价值入账 |
| 合作合力 / 平分 | 先算 ×1.5,再走四叶草,最后按现有规则平分(`floor(v/2)` 给帮手) |

| 单人星级 | 尾声收入计入 `p.roundGain`,影响星级和实时"★2!" |

| 快速模式 `?fast=1` | 触发时刻按比例缩放,数量不变 |

## 4. #9 手感强化包(三个模式)

只有**顿帧**影响逻辑(规则 2 生效、规则 1 关闭)。其余都只影响画面和声音,而且不能调用 `Math.random()`。

| 项 | 规则 |
|---|---|
| 顿帧(逻辑) | 钩子抓住 `it.value ≥ 300` 的物品时(`onHookHit` 成功抓取,`value` 是生成时的原值,不含加成),设 `G.hitStop = 0.06`。`update` 在 `play` 屏遇到 `G.hitStop > 0` 时只减去 `dt`,不调用 `updatePlay`,所以计时器、钩子、物品、危险物、事件和拔河计时都停住,两名玩家一起停。不叠加,取最大值。`G.stats.hitStops++` |
| 大收获时刻 | 单次入账 ≥ $500(`addMoney` 的最终值):以矿工为中心镜头推近 1.0→1.04→1.0(0.3 秒),一圈金色光环,20 枚金币粒子(`fxRand`),新音效 `bigwin`。`G.stats.bigWins++` |
| 滚动金币 | HUD 上显示的金币数向真实值滚动,速度 `max(300, |差值|×6)` 每秒,只在绘制时用。合作的团队金币同样滚动。逻辑和测试读取的仍是真实值 |
| 绳子吃力 | 拉回重量 ≥ 3 的物品时,绳子有 ≤ 2 px 的正弦抖动;每 0.45 秒一声吱呀,音高 = `220 / sqrt(weight)` Hz |
| 差一点! | 钩子伸出过程中,钩尖离某个 `value ≥ 300` 的物品距离 < 判定半径 + 14 px,但本次最终空手收回:收回完成时在该物品上方飘"差一点!"(灰白,24 号字)。每次发射最多一次。`G.stats.nearMiss++` |
| 最后 10 秒 | `G.time ≤ 10` 且未超时:每秒一声心跳(`heartbeat` 音效),屏幕四周红色暗角,透明度 0.15 呼吸 |
| 重物落地 | 交付 `weight ≥ 5` 的物品时,`G.shake = max(G.shake, 0.15)`,绞盘处扬起尘土(`fxRand`) |
| 减少特效(V 键) | 任何屏幕按 **V**(`KeyV`)切换,存 `localStorage['goldminer.reduceFx'] = '1' | '0'`,读写沿用 `lsGet/lsSet`。开启时关掉:所有震屏(包括第一阶段已有的)、镜头推近、光环和闪光、暗角呼吸(改为静态 0.1)。右下角显示 1.5 秒提示"V 特效:关"或"V 特效:开"。**不改变任何游戏结果** |
| 已删除 | 连击音高、连击条,以及任何"花式/反弹"表现 |

`G.stats = { finaleSpawned, finaleBonus, hitStops, bigWins, nearMiss }`,每局开始(`startGame`)时清零。`finaleBonus` 累计尾声 ×1.5 带来的额外金额。

## 5. 挑战性重做(规则 2)

### 5.1 设计原则

- **第 1 关是上手关**:目标低,并且保证不会因为大石头挡路而开局即输(§7-d)。
- **从第 2 关起目标追着高手跑**:每关增量接近熟练玩家的单关平均收入,所以每关都有压力,前面攒下的余量也很快会被吃掉。
- **场地和物品不变**(D12):挑战只来自目标曲线、商店涨价和黄金尾声(尾声物品都在深处,要瞄准才拿得到)。
- **商店是取舍,不是白送**:涨价更快,花钱会直接减少离累计目标的余量。

### 5.2 目标曲线(累计,规则 2)

```
// 修订 1:前缓后陡
SOLO_TARGETS_V2   = [1200, 4000, 7600, 11800, 16400, 21600, 27300, 33300]   // 增量 1200,2800,3600,4200,4600,5200,5700,6000
VERSUS_TARGETS_V2 = [ 700, 3000, 6100,  9600, 13500, 17900, 22700, 27800]   // 每人;增量 700,2300,3100,3500,3900,4400,4800,5100
COOP_TARGETS_V2   = [3000, 8200,14900, 22700, 31300, 40900, 51500, 62700]   // 团队;增量 3000,5200,6700,7800,8600,9600,10600,11200
STAR_MULT_V2      = [1.05, 1.3]
```

规则 1 的三组目标和 `STAR_MULT = [1.5, 2.0]` 保持原样。`targets()`、`starsFor`、`starGoal` 都改为从 `R` 读取。

单人星级(规则 2):过关 1★;本关收入 ≥ 1.05×本关增量 2★;≥ 1.3×增量 3★。

- 选 [1.05, 1.3] 的原因:用 [1.0, 1.25] 时熟练平均 13.7★,接近上限。
- 不能再降,因为 3★ 会送 1 根炸药:阈值更严,3★ 变少,送的炸药也变少。实测 [1.1, 1.35] 时熟练平均 12.5★,但种子 1–200 的全通率掉到 44%。

**曲线形状**:第 1 关不变;从第 2 关起,增量逐关变大,在第 8 关回到原来的终点(对战按新规则重新定了终点)。合作曲线的累计形状和单人相同:第 k 关目标 = 3000 + (单人第 k 关 − 1200)/(33300 − 1200) × 59700。

### 5.3 场地与物品:和第一阶段相同(D12)

- 物品数 `round(28 + 1.5r ± 2)`。
- 保底 `max(1700, inc×K + 500) × hazardBoost`,K:单人和合作 2.1,对战 2.7。这里的 `inc` 取规则 2 的目标增量。
- 物品总数上限仍是 66(含危险物占位)。目标提高以后,合作和对战后期的 `need` 常常超过上限能放下的价值,这时以上限为准。
- 权重、垃圾重量、危险物、事件概率、角色被动全部不变。
- 对战中一方被淘汰后,幸存者的场地照第一阶段规则生成(只按存活玩家判断可达),不减半。
- **唯一的生成改动**是第 1 关的公平规则,见 §7-d。

### 5.4 经济:和第一阶段相同(D12)

神秘袋、金猪、宝箱、金蛋、沙漏 +8 秒、空钩回收 900 px/秒,都不变。

### 5.5 商店涨价

- 价格公式(对战/合作的 `openShop` 和单人的 `soloOffers` 都改):`round(base × (1 + 0.30×(round−1)) × rand(0.85, 1.15) / 5) × 5`。第 8 关的价格是基价的 3.1 倍(规则 1 是 2.05 倍)。
- 单人星级折扣、3★ 送炸药、刷新货架价格 `30 + 15×round + 30×刷新次数` 都不变。
- 用"熟练机器人 + 买东西"实测,种子 1–100,修订 1 之前的目标曲线(修订 1 没有改涨价率,所以没有重测),优先级是 大力药水 > 加速齿轮 > 鉴定书 > 磁铁钩 > 炸药 …:

  | 熟练 8 关全通 | 不买 | 谨慎买(买完仍高于 目标+50% 下一关增量) | 激进买(买到只剩刚好够本关目标) |
  |---|---|---|---|
  | 单人 | 53% | 65% | 71% |
  | 对战 | 49% | 46.5% | 49.5% |
  | 合作 | 46% | 40% | 48% |

  单人买东西明显有回报(单人还有星级折扣);对战和合作基本持平,乱买还会变差。所以买不买、买什么是取舍,不是必选。

### 5.6 对战一人淘汰即结束(修订 1,D15)

- 规则 2 下 `R.versusEndOnElim = true`,规则 1 下为 `false`(保持第一阶段:幸存者可以继续闯关)。
- 对战一关结算后,只要有玩家被淘汰(没达标,也没有金牌),`afterResults` 就直接 `finishGame()`,不进商店。
- **胜负**:
  - 只有一人被淘汰 → 另一人获胜;
  - 两人同一关都被淘汰 → 金币多者胜,相同则平局(现有规则);
  - 两人都通过第 8 关 → 金币多者胜(现有规则)。
- 结算页按钮文字:本局会结束时显示"按空格查看最终结果"。
- 用金牌保住的玩家不算淘汰,游戏继续。
- **"8 关全通"的统计口径**(校准和 AC 用,按每名玩家):本局进行到第 8 关,并且该玩家通过了第 8 关。也就是终局时 `G.round === 8 && p.alive`。对手提前出局、本局在第 k 关结束时,获胜的一方记"通过 k 关",不算全通。
- **最终得分**(§8):对局结束时的金币。`rounds`:存活方记 `G.round`(结束时的关数,他通过了这一关),被淘汰方记 `p.elimRound`。

### 5.7 不变的东西

对战的淘汰条件(除 §5.6 的结束规则外)、合作金牌、拔河、合力、闪电瓶、护盾、6 个事件、4 个主题、6 个角色、商店商品表和单人刷新规则,全部不变。
