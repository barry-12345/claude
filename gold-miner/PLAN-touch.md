## 0. 一页速览

## 1. 设备识别(推荐方案)

```js
const mq = q => window.matchMedia && matchMedia(q).matches;
const TOUCH_UI = /[?&]touch=1/.test(location.search) ? true
               : /[?&]touch=0/.test(location.search) ? false
               : mq('(pointer: coarse)') || (navigator.maxTouchPoints > 0 && !mq('(any-pointer: fine)'));
```

- **手机、平板**:主指针是粗指针 → 触屏界面(只开单人)。
- **带触屏的笔记本 / 二合一电脑**:主指针是鼠标或触控板(`pointer: fine`)→ 电脑界面,三个模式都能玩。这时如果用户点按屏幕,也接受点按:按钮可以点,场地点按 = 发射;但不额外画触屏按钮。
- **接了键盘的平板**:默认是触屏界面。在触屏界面下,只要收到一次真实键盘的游戏按键(`keydown` 且 `e.isTrusted`),就解锁双人卡片,提示"检测到键盘,已开放双人模式"。见 Q2。
- 在 `G.touchUI` 上暴露结果,并提供 `__game.setTouchUI(bool)` 供测试使用。

## 2. 主菜单(触屏界面)

- 单人卡片照常,并且默认选中。如果 `localStorage` 里记的是 `versus` 或 `coop`,在触屏界面下也当作单人。
- 对战、合作卡片置灰(透明度 0.4,加锁形图标),卡片下方写"双人模式请在电脑上用键盘游玩"。点按置灰卡片:卡片轻轻晃一下,并弹出 1.5 秒同样的提示,模式不变。
- 规则面板只显示单人规则。操作说明改为:"点按屏幕 发射钩子 · 💣 按钮 使用炸药 · ⏸ 暂停"。
- 图鉴按钮"图鉴 ▶"可以点按翻页,相当于 Tab。

## 3. 视口与手势

- `<meta name="viewport" content="width=device-width,initial-scale=1,maximum-scale=1,user-scalable=no,viewport-fit=cover">`
- CSS:
  - `html, body, canvas { touch-action: none; overscroll-behavior: none; -webkit-user-select: none; user-select: none; -webkit-touch-callout: none; -webkit-tap-highlight-color: transparent; }`
  - `body { position: fixed; inset: 0; }`,防止 iOS 下拉弹跳和下拉刷新。
- JS:
  - 画布上的 `touchstart / touchmove / touchend` 用 `{ passive: false }` 监听,并调用 `preventDefault()`,防止双击缩放、滚动和长按菜单;
  - `gesturestart / gesturechange`(iOS 双指缩放)调用 `preventDefault()`;
  - `dblclick` 调用 `preventDefault()`;
  - 菜单不用 `click`,一律用 `pointerdown` 响应,避免 300 ms 延迟。
- **全屏按钮**(右上角 ⛶):调用 `document.documentElement.requestFullscreen({ navigationUI: 'hide' })`。成功后尝试 `screen.orientation.lock('landscape')`,失败就忽略。
  - 浏览器不支持 Fullscreen API 时(例如 iPhone Safari),不显示按钮,改为在主菜单显示一次小字提示"添加到主屏幕可全屏游玩"。
  - 同时加上 `<meta name="apple-mobile-web-app-capable" content="yes">` 和 `<meta name="mobile-web-app-capable" content="yes">`。

## 4. 屏幕方向:必须横屏

- 竖屏(`innerHeight > innerWidth`)时,盖上全屏遮罩:旋转手机的图标 + "请横屏游玩"。如果正在游戏中,自动暂停(`pauseGame()`);转回横屏后停在暂停菜单,由玩家点"继续"。
- **为什么不做竖屏布局**:
  1. 游戏是按 1280×720(16:9)设计的。竖屏时缩放系数只有约 0.29,字号只剩 3–4 px。
  2. 如果重新做竖屏布局,就要改场地几何:绞盘位置、摆角、可达范围、物品密度。这样第二阶段校准好的难度、排行榜分数的可比性和回归测试都会失效。
  3. 抓物品主要靠横向的角度判断,横屏的视野本来就更适合。

## 5. 缩放、安全区与可读性

- 画布放在**安全区之内**。读取 CSS `env(safe-area-inset-*)`:用一个隐藏的 div 设成 `padding: env(...)`,再读计算后的样式。
  - 可用尺寸 = `innerWidth − 左右安全边距`、`innerHeight − 上下安全边距`;
  - 缩放 `s = min(可用宽/1280, 可用高/720)`,居中显示;安全区以外填充背景色;
  - 测试用的覆盖参数:`?safe=左,上,右,下`(单位 px)。
- 目标机型(横屏,逻辑像素):

  | 机型 | 视口 | 安全区左右 | 缩放 s |
  |---|---|---|---|
  | iPhone SE / 8 | 667×375 | 0 | 0.52 |
  | iPhone 13 / 14 | 844×390 | 47 / 47 | 0.54 |
  | Pixel 7 | 915×412 | 约 0–24 | 0.57 |
  | iPhone 14 Pro Max | 932×430 | 59 / 59 | 0.60 |

- **触摸目标 ≥ 44 CSS px**。最小缩放是 0.52,所以按钮在游戏坐标里至少 88×88。
- **可读性**:触屏界面下 HUD 的关键文字(金币、目标、倒计时、星级说明、商店价格)在游戏坐标里至少 24 px,最小机型上约等于 12.5 CSS px。为此,触屏界面用一套 HUD 布局:放大字号,去掉次要文字(例如纪录同期的小旗说明)。见 Q3。
- 继续沿用 `DPR ≤ 2` 的上限,另外加自适应降级(§9)。

## 6. 游戏中的触屏操作(单人)

| 操作 | 方式 |
|---|---|
| 发射钩子 | 点按**画面任意位置**(按钮区域除外),在 `pointerdown` 时立即触发,等价于 `handleKey('KeyS')` |
| 炸药 | 左上天空区域的炸药按钮(游戏坐标 x 40–160,y 92–182,即 120×90),显示剩余数量。只有拉回物品时可用,不可用时置灰。等价于 `KeyW` |
| 暂停 | 右上天空区域的暂停按钮(x 1150–1250,y 92–182),等价于 `KeyP` |
| 按钮位置 | 放在 HUD 面板下方、矿场上方的天空带(y < 190),**不压在矿场上**,所以点按矿场永远是发射 |
| 多点触控 | 每个 `pointerId` 独立处理:一根手指按着场地,另一根手指点炸药也必须生效。只有 `pointerdown` 有动作,`move/up` 不触发任何操作 |
| 拔河 | 单人模式不会发生,不做 |

## 7. 菜单点按

先做一个统一的点击区域表:绘制时用 `UI.btn(id, x, y, w, h, onTap)` 登记,`pointerdown` 时把坐标换算到游戏坐标,再按表命中。`onTap` 尽量调用与按键**相同的处理函数**,或者合成同一个按键码,保证行为一致。

| 屏幕 | 点按操作 |
|---|---|
| 主菜单 | 点单人卡片 → 选中并进入角色选择;置灰卡片 → 提示(§2);"图鉴 ▶" → 翻页;⛶ 全屏 |
| 角色选择 | 点角色卡片 → 选中(高亮);再点同一张卡片,或者点"开始"按钮 → 确认,0.8 秒后自动开始(和现在一样,也可以点"立即开始");"返回" → 主菜单 |
| intro | 点任意位置 → 跳过(等价于空格) |
| 结算 | "继续"按钮(0.4 秒后可以点),等价于空格 |
| 商店 | 点商品卡片 → 选中;再点已选中的卡片,或者点"购买"按钮 → 购买;刷新卡同理;"准备好了":第一次点进入"已准备"(和第二阶段键盘的二次确认一样,1.5 秒内有效),第二次点开始下一关 |
| 暂停菜单 | 每一行都能点(继续 / 重新开始 / 主菜单),另外加"声音 开/关"和"特效 开/关"两个开关(对应 M 键和 V 键) |
| 终局 | "再来一局"(等价于空格)和"主菜单"(等价于 Esc)两个按钮 |

## 8. 声音解锁(iOS Safari)

- 在第一次 `touchend` / `pointerup` 时调用 `Snd.init()`。之后 `ctx.resume()`,并播放一个 1 帧的静音 buffer,用来解锁 iOS。
- 页面在 `visibilitychange` 时:隐藏 → `suspend`;显示 → `resume`,但如果游戏处于暂停状态就不恢复。
- 解锁之前不报错,直接跳过所有音效。

## 9. 性能

- **目标**:中端手机(Pixel 6a / iPhone 11 级别),游戏中帧率中位数 ≥ 55 fps,1% 低帧 ≥ 40 fps。逻辑是固定步长,掉帧不会影响结果。
- **DPR 自适应**:
  - 起点是 `min(devicePixelRatio, 2)`;
  - 连续 2 秒平均帧时间 > 22 ms 时,降一档:2 → 1.5 → 1;
  - 不会自动升回;
  - 降档时重建背景缓存。
- 触屏界面下粒子总数上限 300;页面隐藏时停止 `requestAnimationFrame` 渲染。
- 逻辑和第二阶段的"减少特效"开关共用:特效关闭时,粒子数再减半。

## 10. 键盘与回归

- 键盘玩法完全不变。触屏界面下也接受键盘输入。
- 电脑界面(`G.touchUI === false`):不画任何触屏按钮,画面和第二阶段完全一样。
- 触屏代码只调用现有的按键处理函数,不修改游戏逻辑,不新增 `Math.random()` 调用。

## 11. 第三阶段提示:手机上输入排行榜名字

- 名字输入用**真实的 DOM `<input>`**(画布上没法弹出系统键盘),属性:`maxlength=12`、`enterkeyhint="done"`、`autocomplete="off"`、`autocapitalize="off"`。
- 横屏时系统键盘大约占半个屏幕。输入浮层固定在**可视区域的顶部**:用 `visualViewport` 的 `resize` / `scroll` 事件重新定位(`top = visualViewport.offsetTop + 8`)。浮层高度 ≤ 可视高度的 40%,保证输入框、"提交"和"跳过"按钮都不会被键盘挡住。
- 提交以后调用 `input.blur()` 收起键盘,并把画布滚回原位。
- 手机只玩单人,所以只会提交单人成绩;对战榜只来自电脑。第三阶段的界面不需要为此做特殊处理。

## 13. 需要用户决定的问题

**Q1. 触屏上的双人模式卡片:置灰,还是隐藏?**
- 推荐:**置灰并写"双人模式请在电脑上用键盘游玩"**。朋友们聊起对战时知道它在哪、为什么手机上不能玩;主菜单的布局也和电脑一致。
- 另一个选项:隐藏,菜单只剩单人一张大卡片,更简洁。

**Q2. 接了实体键盘的平板,要不要解锁双人模式?**
- 推荐:**要**。触屏界面下一旦收到真实键盘按键,就开放双人卡片,这时就和电脑一样。
- 另一个选项:触屏设备一律只能单人,规则最简单。

**Q3. 触屏界面的 HUD 要不要单独放大字号?**
- 推荐:**要**。最小的手机上,原版 11 号字只有约 6 CSS px,看不清;放大后布局会和电脑版有些不同。
- 另一个选项:保持原版布局,只加按钮。改动少,但小屏手机上的文字很难读。
